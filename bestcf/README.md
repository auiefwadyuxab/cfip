# BestCF 自动提取与同步

由 Cloudflare Worker Dashboard 中配置的 Cron 触发 `bestcf.yml`；手动运行也执行相同的同步流程。程序按 `url` 的四行顺序同步面板；每个面板当前按最多49条处理。

## GitHub Secrets

在 `Settings → Secrets and variables → Actions` 添加两个 Secret：

- `ADMIN`：四个面板共同的管理员密码。
- `url`：四个后台完整地址，一行一个，必须按你设定的四个面板顺序填写；地址不要写入公开文件。

每行格式为 `https://你的域名/admin`，不要添加名称或其他文字。

## 文件

- `bestcf/bestcf.py`：抓取、分配和同步脚本。
- `bestcf/yuan.txt`：其中的去重链接参与第2个面板分配；不足49条时由普通链接溢出补足。
- `bestcf/bestcf.txt`：完整抓取结果，先放 `sub://`，空一行后放普通链接。
- `bestcf/bestcf.log`：记录运行数量、分配和结果，不重复保存完整链接；完全无变化时当前程序不更新日志，失败时会覆盖写入失败摘要。

## 面板分配规则

| `url` 行 | 当前实现 |
|---:|---|
| 1 | 普通链接前49条 |
| 2 | `yuan.txt` + 超过98条后的普通链接 |
| 3 | 全部 `sub://` 订阅 |
| 4 | 普通链接第50～98条 |

第2行目标数量超过49条时，程序会报告无法分配并停止，不会静默截断链接。相同 URL 家族的 `topN` / `ips=` 变体只保留最大档位。输出顺序采用稳定策略：旧文件中仍存在的链接保持原位置，新链接按本轮抓取顺序追加；顺序不影响面板集合比较。

## 运行

- Cloudflare Worker 按现有 Cron 定时触发 `bestcf.yml`；手动运行 Actions 也执行同一套正式同步流程。
- bestcf 正常完成后，`sub` 和 `vps789` 工作流自动启动；本次没有链接或面板变化也一样会启动。
- bestcf 执行失败时，不启动下游。若面板只完成了部分写入，已成功写入的面板保持现状；下一次运行会重新读取四个面板，只更新仍不一致的面板。
- 若链接集合与面板内容均无变化，不重写输出和日志，也不产生 Git 提交。
- 失败时工作流只提交本次 `bestcf.log` 诊断记录，不会提交未完成的 `bestcf.txt`。
